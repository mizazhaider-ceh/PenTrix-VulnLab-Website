Install PenTrix VulnLab

Two ways to get the lab running on your own machine. Docker is the recommended method: one command, isolated sandbox, no dependency surprises. The local Node method is for people who want to hack on the code itself.

Docker method Local Node method

Prerequisites

  • git, to clone the repository.
  • Docker Desktop (Windows or macOS) or Docker Engine (Linux), for the recommended method.
  • ~2 GB free disk space for the images and the database.
  • Node 20+, only if you take the local method instead of Docker.

Method 1: Docker (recommended)

Clone the repo

git clone https://github.com/mizazhaider-ceh/PenTrix-VulnLab.git
cd PenTrix-VulnLab

Build and start the container

docker compose up --build

The first build installs dependencies and compiles the database module, so it takes a few minutes. The first boot takes about 20 seconds while the lab generates your personal flags.

Open the lab

Open http://localhost:3000 in your browser. You should see the module grid with all 29 modules.

What the Docker setup does for you

  • Binds to 127.0.0.1 only, so the vulnerable app is reachable from your machine and nowhere else.
  • Drops all Linux capabilities (cap_drop: ALL) and runs as the non-root node user.
  • Limits the container to 512 MB RAM and 1 CPU.
  • Ships a healthcheck that hits the home page every 30 seconds.
  • Persists your progress and flags in ./data (a gitignored bind mount), so stopping the container never wipes your work.

Method 2: Run it locally with Node

Use this if you want to edit the code, write challenges, or run the regression suite. You need Node 20+ installed.

Clone and install dependencies

git clone https://github.com/mizazhaider-ceh/PenTrix-VulnLab.git
cd PenTrix-VulnLab
npm install

Start the app

npm start

Then open http://localhost:3000 in your browser.

Linux build tools. The better-sqlite3 package needs to compile at install time. On Linux, install python3, make, and g++ before running npm install. The Dockerfile installs exactly these in its build stage for the same reason.
Set SESSION_SECRET for shared or graded use. The app falls back to an insecure dev secret when this is unset, which is fine for solo labs only. For anything graded or shared, start with a private value, for example SESSION_SECRET=put-something-private-here npm start, or uncomment the variable in docker-compose.yml and set your own value.

What happens on first boot

On the first start, the app generates 201 random flags into a local SQLite database at data/vulnlab.db. Each flag looks like PENTRIX{ followed by 32 random hex characters. The data/ directory is gitignored, and no flag literal exists in any tracked file, so reading the source on GitHub spoils nothing. Your flags are generated on your machine, which means your flags differ from everyone else's.

Verify it works

Check the home page

Open http://localhost:3000. You should see the module grid: 29 modules with search and difficulty filters.

Open a module

Pick any module and open its first challenge. If the briefing loads and the challenge page renders, your install is healthy.

Troubleshooting

Port 3000 is already in use
Something else is listening on 3000. Stop the other process, or change the port mapping in docker-compose.yml (for example "127.0.0.1:3001:3000") and start again.
Docker: permission denied (Linux)
Your user is not in the docker group. Either run Docker commands with sudo, or add yourself to the group and log out and back in.
./data is not writable (Linux)
The container runs as user node (uid 1000). The Dockerfile comments call this out: on Docker Desktop it just works, but on Linux make sure your user can write to ./data, or set ownership with sudo chown -R 1000:1000 data.
The first build is slow
That is normal: it runs a clean npm ci and compiles better-sqlite3 inside the build stage. Be patient. You only need --build when dependencies or the Dockerfile changed; plain docker compose up is enough on later starts.
I want fresh flags
Flags live in the bind-mounted ./data folder, so removing the container alone does not reset them. Stop the stack with docker compose down -v, delete the database file (data/vulnlab.db), then start again with docker compose up --build. The lab will generate a brand-new set of 201 flags on boot.
The page is not loading
Check the container logs with docker compose logs. The healthcheck needs up to 20 seconds on first boot while flags are generated, so give it a moment before treating a blank page as a failure.

Uninstall

Remove the container and its volumes

docker compose down -v

Delete the folder

cd ..
rm -rf PenTrix-VulnLab

Your flags and progress were in ./data, so deleting the folder wipes them too.

Safety first. PenTrix VulnLab is intentionally vulnerable. Run it only on your own machine, on localhost. The Docker setup binds to 127.0.0.1 only for a reason: never expose this lab to the internet or to any network you do not fully control.
