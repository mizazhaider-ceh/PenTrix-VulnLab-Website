How flags work

Every flag looks like PENTRIX{ followed by 32 random hex characters, then }. They are random per install: generated on first boot into a gitignored SQLite database. No flag literal exists in any tracked file, so reading the code on GitHub reveals nothing.

That means flags cannot be leaked, copied from a write-up, or pasted from someone else's install. The only way to capture a flag is to exploit the vulnerability the way an attacker would.

Want a fresh start? Delete the database and reboot the lab. You get a brand new set of flags, and all progress resets.

Hint ladders

Stuck is part of learning, so every challenge has a 3-level hint ladder:

  1. Level 1, nudge: points you at the right idea without naming it.
  2. Level 2, stronger hint: names the technique or the place to look.
  3. Level 3, near-solution: almost walks you through it, but still leaves the last step to you.

Full walkthroughs live in SOLUTIONS.md in the repo. They teach technique, never flags: the flags are random per install, so a walkthrough cannot hand you one.

Claiming flags

Most flags award automatically the moment you genuinely exploit the vulnerability. The lab checks that the exploit really happened, not that you faked the response.

For XSS-style beacon challenges, there is one catch: the server cannot see your screen. So your payload must send the page-token beacon back to the lab. Every such page has a "How to claim this flag" box explaining exactly how.

Shortcuts earn nothing. Beacons without a token get a 400. Replaying a token you already used gets a 400 too.

Break-then-fix

Attackers find bugs. Engineers fix them. PenTrix makes you do both.

After you capture a flag, you can open the vulnerable code and patch it yourself. The lab then re-runs the original exploit against your fix in an isolated sandbox. If the exploit fails and the app still works, you earn a fix badge on that challenge.

Scenarios

Visit /scenarios for three story-driven kill chains:

  • Shop Takeover
  • API Heist
  • Ghost in the CMS

Each scenario stages its challenges so they unlock in order, chaining individual bugs into one full attack story. Finish the chain and you capture the scenario flag at the end.

Paths and certificates

Visit /paths for three guided career paths:

  • Zero to Web Pentester
  • API Hacker
  • Authentication Assassin

Each path lists its prerequisites, orders the challenges into a curriculum, and tracks your progress as you finish them.

Finish a path and you earn a PNG certificate. It carries a verification code like PTX-XXXXXXXX that is bound to your install, and anyone can check it on the path's /verify page.

Resetting

To reset everything (fresh flags and clean progress):

rm -rf ./data

Then reboot the lab and it generates a new set of flags on first boot.

If you run with Docker Compose:

docker compose down -v

FAQ

Is it safe to run?

Yes. The lab runs localhost-only and never touches the internet. The container drops Linux capabilities and is limited to 512M of memory and 1 CPU. Keep it off shared networks and run it only on your own machine.

Can I deploy it publicly?

No, never. PenTrix is intentionally vulnerable, so putting it on the public internet would hand attackers a working exploit playground on your infrastructure. Run it on your own machine or an isolated lab network only.

I solved a challenge but got no flag. Why?

The flag only awards for a genuine exploit. If you bypassed the check, faked a response, replayed someone else's token, or the exploit was not real, the lab rejects it (shortcuts earn 400s). Re-run the actual attack and the flag will land.

Do I need Burp Suite?

No. A browser and curl are enough for everything in the lab.

Where do I start as a beginner?

Start with the Zero to Web Pentester path. It assumes nothing and teaches the fundamentals in order, ending with a certificate.

Can I add my own challenges?

Yes. Follow the module contract (MODULE_CONTRACT.md in the repo): one file per challenge under modules/<id>/challenges/, and it auto-mounts with hints, flags, and scoring. Until the simple challenge-builder format lands, pull requests with new challenge ideas are welcome.
